:class:`~filelock.ReadWriteLock` locks again after a ``release()`` interrupted by an exception from a signal handler,
the async read-write locks stop admitting tasks into a hold whose backend release failed and no longer keep memory for
each acquire that times out or is canceled, and :class:`~filelock.AsyncFileLock` no longer hangs in ``release()`` after
a few hundred acquires gave up behind a waiting one.
